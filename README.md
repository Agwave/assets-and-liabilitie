# 个人资产负债看板

> 一个**只读**的资产 / 负债看板。**Windows 桌面应用**和**网页**共用一套前端，
> 数据是一份本地 YAML —— 没有后端、没有账号、没有数据库。

## 为什么值得一看

**8 MB 的桌面应用。** 用 Tauri 而不是 Electron —— Rust 编译成原生二进制，界面借
Windows 自带的 WebView2，不把 Chromium 塞进去。同一个应用用 Electron 做要 150 MB 起。

**配色是算出来的，不是挑的。** 资产用绿、负债用红，而绿红恰好是红绿色盲最经典的
混淆对。我没有凭眼睛选色，而是固定一侧、扫另一侧候选，逐组合跑验证器，直到
**明度带 / 色度下限 / 对比度 / 色盲可分辨性**四项检查在明暗两种模式下全部通过：

| 模式 | 资产      | 负债      | 色盲模拟 ΔE | 正常视觉 ΔE |
| ---- | --------- | --------- | ----------- | ----------- |
| 浅色 | `#078a07` | `#e34948` | 8.5         | 32.9        |
| 深色 | `#0d940d` | `#e06a6a` | 9.6         | 32.3        |

**配置写错会被读懂。** YAML 有几个会**静默出错**的写法：`1,600,000` 和 `1_600_000`
都会被解析成字符串（下划线是 JS 的写法，YAML 不认），`amout:` 少打一个字母不报错、
只会安静地变成 `undefined`。这些在应用里都会渲染成一张能读的错误页：

```
配置文件有 3 处问题

· 资产 第 2 条的 amount 是字符串 "1,600,000" —— YAML 里数字不能带千分位逗号、
  下划线或引号，它们会让整串变成字符串。去掉分隔符，写成 1600000。
· 资产 第 4 条有一个不认识的字段 `amout`，是不是想写 `amount`？
可用的字段只有 name / amount / note。
```

**构建产物里不含任何数字。** 数据一律**运行期**读 —— 桌面端由 Rust 读本地文件、
网页端 fetch 一份同步副本。所以改一次数据不用重新打包应用；CI 构建时也根本
拿不到你的资产（仓库里没有数据文件，构建机无从获取）。

**一套代码，两种形态。** 桌面和网页的差别总共只有一处：`lib/data-source.ts` 里
桌面走 `invoke`、网页走 `fetch`。解析、校验、汇总、渲染全部共用。

## 快速开始

```bash
pnpm install
cp config/assets.example.yaml config/assets.yaml   # 首次必须做
pnpm dev                                           # http://localhost:3000
```

改了 `config/assets.yaml` **刷新页面即可**，不用重启 dev server。

## 架构

两个形态的产物是**同一份** `out/`（Next.js 静态导出），差别只在数据从哪来：

```
桌面    WebView2 窗口 → 加载 out/ → invoke → Rust 读本地文件
网页    浏览器       → 加载 out/ → fetch  → ledger.json
                              ↓
                 两端拿到的都是同一件东西：一段 YAML 文本
                              ↓
             同一套前端：解析 → 校验 → 汇总 → 渲染
```

Rust 只把文件读成字符串，**不做任何解析** —— 解析和校验全在前端那套 TypeScript 里。
在 Rust 里再实现一遍那套规则，两份实现迟早会不一致。

## 数据流与校验分层

```
数据源          lib/data-source.ts     桌面 invoke / 网页 fetch，返回一段 YAML 文本
   ↓
形状校验        lib/parse-ledger.ts    YAML 语法、未知字段、类型（纯函数，两端共用）
   ↓
业务规则        lib/ledger.ts          金额正负、重名、空表 + 汇总与排序
   ↓
界面            components/            状态机 → 六种状态各有对应界面
```

两层校验分开报：形状不对时数据还不是 `Entry[]` 的样子，跑业务规则只会给出误导性结果。
**每一层内部一次报全**，不让人改一个跑一次。

`lib/parse-ledger.ts` **返回结果而不是抛错** —— 它跑在应用里，错误要渲染成一张能读的
错误页，而不是把界面炸掉。

## 配置

`config/assets.yaml` 只放资产项和负债项，顶层只有两个键：

```yaml
assets:
  - name: 自住房
    amount: 1600000
    note: 按 2026-08 同小区成交价估值
  - name: 招商银行 · 活期
    amount: 85000

liabilities:
  - name: 住房商业贷款
    amount: 980000
    note: 年利率 3.1%，剩余 18 年
```

三条规矩：**金额写正数**（正负由它在 `assets` 还是 `liabilities` 下决定）、
**不要带千分位逗号 / 下划线 / 引号 / ¥ 符号**、**同一侧名字不能重复**。
顺序随便写，页面按金额降序自己排。

页面标题、副标题、页脚备注是固定信息，在 `config/site.ts` 里。

## 桌面应用

**装完之后，一个文件夹里既有程序又有数据：**

```
%LOCALAPPDATA%\个人资产看板\
├── 个人资产看板.exe
├── assets.yaml          ← 你的数据，第一次打开应用时创建
└── uninstall.exe
```

第一次打开会提示还没有配置文件，点「创建配置文件」→「打开配置文件夹」，
用任意编辑器改完保存，回应用点刷新即可 —— **不用重新打包**。

> **卸载前会自动备份**到 `文档\AssetsLedger-backup\`。配置文件在安装目录里，
> 而卸载器会整个删掉那个目录 —— 不备份的话，卸个软件就把资产数据一起删了。

> 首次运行 Windows 会弹「已保护你的电脑」，点「更多信息」→「仍要运行」。
> 没有买代码签名证书（一年几百到几千，个人自用不值当）。

### 发一个版本

```bash
git tag v0.1.0
git push origin v0.1.0
```

CI 自动构建并把安装包挂到 [Releases](../../releases)，永久可下载。
改代码时调试用 Actions 页面的 **Run workflow**，产物挂在那次运行的 Artifacts 里（保留 90 天）。

> 注意用 **Run workflow** 起一次新运行，而不是在旧运行上点 **Re-run** ——
> 后者重跑的是**那一次对应的旧提交**，即使 main 已经往前走了。

## 开发

| 命令                 | 作用                                           |
| -------------------- | ---------------------------------------------- |
| `pnpm dev`           | 开发服务器（网页形态）                         |
| `pnpm build`         | 类型检查 + 静态导出到 `out/`                   |
| `pnpm serve`         | 预览 `out/`（先 `pnpm build`）                 |
| `pnpm check`         | 快速自检：排版 + lint + 类型                   |
| `pnpm check:rust`    | 检查 Rust 能不能编译（改 `src-tauri/` 后必跑） |
| `pnpm desktop:build` | 打 Windows 安装包（需要完整 Rust 工具链）      |

**没有测试框架，这是刻意的。** 这个项目绝大部分逻辑是「把配置渲染成 HTML」，
为它搭框架的收益低于维护成本。取而代之的是两件事：**类型系统**承担编译期约束，
**运行期校验**承担数据约束 —— 两者都直接对用户可见（校验的产出就是上面那张错误页）。

### `pnpm check:rust` 为什么存在

开发机是 WSL，没有 Windows，桌面的「装完能不能跑」只能靠 CI 加真机。
但 **Rust 代码本身是能在本机验的**：把编译目标换成 Windows
（`cargo check --target x86_64-pc-windows-gnu`），cargo 就不会去碰 Linux 上
缺失的 webkit2gtk / dbus 系统库 —— 而那本来就是真正要编的目标。
`tauri-build` 要的 `windres` 用一个空文件桩顶替：`cargo check` 只做类型检查、
不链接，那个资源文件的内容用不到。

### 防止数据被误提交

这个仓库是公开的，而它管的偏偏是个人财务数据 —— 误提交一次就是全网可见，
fork 和爬虫的副本收不回来。所以有**两道网**：

| 检查     | 位置                          | 挡住什么                               |
| -------- | ----------------------------- | -------------------------------------- |
| Git 钩子 | `.githooks/pre-commit`        | 本地提交时，暂存区里出现数据文件就拦下 |
| CI 检查  | `.github/workflows/guard.yml` | 兜住 `--no-verify` 和网页端提交        |

钩子靠 `core.hooksPath` 生效，`pnpm install` 会自动配好。两道都只查**路径** ——
把数字粘进文档这类内容层面的漏它们管不了，那种事只有人自己能判断。

## 设计上的取舍

**数据运行期读，不烤进产物。** 早期版本在构建期把 YAML 渲染进 HTML，结果是改一次
数据就要重新打包一次应用 —— 那还不如用网页。现在产物里一个数字都没有。

**条形榜而不是环形图，而且是单色的。** 条目是平铺的，有十几条 —— 环形图的扇区上限
在 6 个左右，再多既画不开也没有那么多色盲可分辨的颜色可用。给每个条配不同颜色，
属于把「长度」这个信息用颜色再编码一遍，白白烧掉唯一的身份通道。

**负债侧没有环形图。** 负债是同一类东西，拆成多个色相等于用颜色编码「第几类」这个
对读者没用的信息。负债率用仪表 + 文字档位（稳健 / 适中 / 偏高 / 高）表达，
颜色从不单独表意。

**页面默认不被搜索引擎收录。** `app/robots.ts` 和 `<meta name="robots">` 两道闸都上了。
