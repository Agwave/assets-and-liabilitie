# 个人资产负债看板

一个**只读**的个人资产 / 负债展示页。数据全部来自配置文件 —— 页面没有编辑入口、
没有数据库、没有接口、没有登录。改数据 = 改一个 TypeScript 文件 + 重新构建。

- Next.js（App Router，静态生成）+ Tailwind v4 + shadcn/ui 约定
- 手机和电脑双端自适应，深色 / 浅色 / 跟随系统三态
- 页面运行时**没有图表 JavaScript**，环形图是构建期生成好的 SVG

## 快速开始

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

## 改成你自己的数据

**只需要动 `config/assets.ts` 这一个文件。** 里面现在是占位示例。

```ts
export const assetCategories = [
  {
    id: "cash", // 唯一标识，别和别的分类重复
    colorSlot: 0, // 环形图配色槽位，0..4，各分类不能撞车
    name: "现金及存款", // 显示名
    description: "随时能取出来的钱",
    items: [
      { name: "招商银行 · 活期", amount: 85_000 },
      { name: "货币基金", amount: 120_000, note: "T+1 赎回到账" },
    ],
  },
  // …
] as const satisfies readonly AssetCategory[];
```

三条规矩：

1. **金额一律写正数**，单位是元。房贷写 `980000`，不是 `-980000` ——
   正负由它放在 `assetCategories` 还是 `liabilityCategories` 决定。
2. **资产分类最多 5 个**（配色槽位只有 5 个验证过的颜色）。想加第 6 类就先合并两类。
3. 改完记得更新 `config/profile.ts` 里的 `asOf`（页头会显示「数据截至 …」）。

写错了不会静默出错 —— `pnpm build` 会直接失败并指出是哪个分类的哪个条目：

```
Error: config/assets.ts 的数据有问题，构建已中止：
  · 资产分类「投资持仓」的条目「债券基金」金额是 -60000 —— 金额必须为正数；
    正负由它属于资产还是负债决定，不要写负号。
```

## 目录结构

```
config/assets.ts           ← 数据源。改数据只改这里
config/profile.ts          ← 名字、副标题、数据截止日期、页脚备注
lib/ledger.ts              ← 账本类型、汇总计算、构建期体检
lib/format.ts              ← 人民币格式化
lib/palette.ts             ← 图表配色槽位（顺序是色盲安全机制，别乱动）
components/allocation-donut.tsx  ← 环形图，手写 SVG
components/net-worth-panel.tsx   ← 净资产 hero + 统计卡 + 负债率仪表
components/category-card.tsx     ← 分类明细卡（含占比条）
app/page.tsx               ← 唯一的页面，组装以上所有
```

## 命令

| 命令             | 作用                                           |
| ---------------- | ---------------------------------------------- |
| `pnpm dev`       | 开发服务器                                     |
| `pnpm build`     | 完整校验：类型检查 + 构建期数据体检 + 静态生成 |
| `pnpm start`     | 预览生产构建（先 `pnpm build`）                |
| `pnpm check`     | 快速自检：排版 + lint + 类型（不含构建）       |
| `pnpm format`    | Prettier 格式化（含 Tailwind 类名排序）        |
| `pnpm lint`      | ESLint                                         |
| `pnpm typecheck` | 只查类型                                       |

**本仓库没有测试框架，这是刻意的。** 站点是纯静态展示，绝大部分逻辑是「把配置渲染成
HTML」，为它搭测试框架的收益低于维护成本。类型系统 + 构建期体检承担了测试的职责。

## 设计上的几个决定

**环形图是手写的 SVG，没有引图表库。** 用 `curl` 拉页面（不执行任何 JS）能看到完整的
5 个扇区 —— 无 JavaScript 环境也能正常看。引 recharts 之类会让整块图表进入客户端包。

**配色是算出来的，不是挑的。** 5 个分类色的顺序跑过色盲安全验证：明暗两种模式下相邻
色相在红绿色盲模拟下 ΔE ≥ 9.4，正常视觉 ΔE ≥ 19.7，对比度全部 ≥ 3:1。扇区顺序**固定
等于配置顺序，不做按金额排序** —— 排序会让任意两个色相变成邻居，上面那个保证就失效了。
金额大小靠图例里始终可见的数值和占比表达。

**负债侧没有环形图。** 负债是同一类东西，拆成多个色相等于用颜色编码「第几类」这个对
读者没用的信息。负债率用仪表 + 文字档位（稳健 / 适中 / 偏高 / 高）表达，颜色从不单独
表意。

**占比条的两个层级用同一个分母。** 卡片条和条目条都是「占该侧合计的比例」，所以条目条
正好拼成卡片条，两层长度可以直接互相比较。

**页面默认不被搜索引擎收录。** `app/robots.ts` 和 `<meta name="robots">` 两道闸都上了。
想公开被搜到的话，两处都要改。

## 部署

标准的 Next.js 静态站点，Vercel 直接导入即可。产物也能导出成纯静态文件（`out/`）丢到
任何静态托管，但因为目前没有用到任何服务端能力，两种方式行为完全一致。

环境变量：**没有**。不存在 `.env` 文件，也不需要在部署平台配任何东西。

## 已知限制

- **各分类只有当前快照，没有历史趋势。** 想做走势图的话，配置结构得改成多期快照数组。
- **只支持人民币。** 没有汇率换算，展示的每个数字都是配置里写的那个数字。
- **金额是手填的，不会自动更新。** 房产估值、基金市值都需要你自己定期改配置。
