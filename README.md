# 个人资产负债看板

一个**只读**的个人资产 / 负债展示页。数据全部来自一份 YAML —— 页面没有编辑入口、
没有数据库、没有接口、没有登录。改数据 = 改一个 YAML + 重新构建。

- Next.js（App Router，静态生成）+ Tailwind v4 + shadcn/ui 约定
- 手机和电脑双端自适应，深色 / 浅色 / 跟随系统三态
- 页面运行时**没有任何图表 JavaScript**，条形榜是纯 CSS 渲染的

## 快速开始

```bash
pnpm install
cp config/assets.example.yaml config/assets.yaml   # 首次必须做，否则构建会报错
pnpm dev                                           # http://localhost:3000
```

## 改成你自己的数据

**只改 `config/assets.yaml` 这一个文件。**

### 为什么它不在 git 里

`config/assets.yaml` 被 `.gitignore` 排除了 —— 里面是你真实的资产数据，
不该进仓库。仓库里提交的是模板 `config/assets.example.yaml`。
新克隆之后先复制一份：

```bash
cp config/assets.example.yaml config/assets.yaml
```

没复制就构建的话，会直接报错并告诉你这条命令：

```
Error: 找不到 config/assets.yaml，构建已中止。

  这个文件被 .gitignore 排除了 —— 里面是你的真实资产数据，不该进仓库。
  从模板复制一份再改：

      cp config/assets.example.yaml config/assets.yaml
```

### 文件长什么样

**这个文件只放资产项和负债项**，没有别的东西。结构是平铺的：
一条记录 = 一个名字 + 一个金额，没有二级分类。

```yaml
assets:
  - name: 自住房
    amount: 1600000
    note: 按 2026-08 同小区成交价估值
  - name: 招商银行 · 活期
    amount: 85000

liabilities:
  - name: 住房商业贷款
    amount: 980000
    note: 年利率 3.1%，剩余 18 年
```

### 标题这些在哪

页头标题、副标题、数据截止日期、页脚备注是**固定信息，不随数据变**，
所以它们在代码里：`config/site.ts`。想让看板换个名字就改那里。

唯一要注意的是 `asOf`（数据截止日期）—— 它跟数据走，但**不会自动更新**，
每期改完资产数据记得回 `config/site.ts` 改这一行。

### 三条规矩

1. **金额写正数**，单位是元。房贷写 `980000`，不是 `-980000` ——
   正负由它放在 `assets` 还是 `liabilities` 下面决定。
2. **金额不要带千分位逗号、下划线、引号或 ¥ 符号**，直接写 `1600000`。
   YAML 会把 `1,600,000` 和 `1_600_000` 当成**字符串**而不是数字
   （下划线是 JS 的写法，YAML 不认）。
3. **同一侧里名字不能重复。**

顺序随便写，页面会按金额从大到小自己排。

### 其他

- `note` 是可选的，显示在名字下面，适合写「年化 2.6%」「按 2026-08 估值」这类口径。
- **`assets` 不能为空；`liabilities` 可以一条都没有**（那就是无负债，页面显示空态）。
- 值里含半角冒号或 `#` 要用引号包起来：`name: "招商银行: 活期"`。
- 顶层只有 `assets` 和 `liabilities` 两个键，多写别的会被构建期校验拒掉。

### 写错了会怎样

不会静默出错。**字段名拼错、类型不对、金额带逗号，构建期全部拦下来**，
并且一次性把所有问题报全，而不是让你改一个跑一次：

```
Error: config/assets.yaml 的内容有问题（共 3 处），构建已中止：
  · 资产 第 2 条的 amount 是字符串 "1,600,000" —— YAML 里数字不能带千分位逗号、
    下划线或引号，它们会让整串变成字符串。去掉分隔符，写成 1600000。
  · 资产 第 4 条有一个不认识的字段 `amout`，是不是想写 `amount`？
    可用的字段只有 name / amount / note。
  · 资产 第 5 条的 amount 是 -30000 —— 金额必须为正数；正负由它放在 assets
    还是 liabilities 下面决定，不要写负号。如果这项已经还清或归零，请整条删掉。
```

开发时改完 `config/assets.yaml` **刷新页面就行，不用重启 dev server**。

## 目录结构

```
config/assets.example.yaml  ← 数据模板，进 git
config/assets.yaml          ← 你的真实数据，被 .gitignore 排除
config/site.ts              ← 标题、副标题、数据截止日期、页脚备注（固定值）
lib/config.ts               ← 读 YAML + 校验字段名/类型，坏配置在构建期报错
lib/ledger.ts               ← 类型、汇总计算、排序、业务规则体检
lib/format.ts               ← 人民币格式化
components/ranking-list.tsx    ← 条形榜（资产和负债共用）
components/net-worth-panel.tsx ← 净资产 hero + 统计卡 + 负债率仪表
components/ui/                 ← 手写的卡片和占比条，没有 "use client"
app/page.tsx                ← 唯一的页面，组装以上所有
```

## 命令

| 命令             | 作用                                           |
| ---------------- | ---------------------------------------------- |
| `pnpm dev`       | 开发服务器                                     |
| `pnpm build`     | 完整校验：类型检查 + 构建期数据体检 + 静态生成 |
| `pnpm start`     | 预览生产构建（先 `pnpm build`）                |
| `pnpm check`     | 快速自检：排版 + lint + 类型（不含构建）       |
| `pnpm format`    | Prettier 格式化（含 Tailwind 类名排序）        |
| `pnpm lint`      | ESLint                                         |
| `pnpm typecheck` | 只查类型                                       |

**本仓库没有测试框架，这是刻意的。** 站点是纯静态展示，绝大部分逻辑是「把配置渲染成
HTML」，为它搭测试框架的收益低于维护成本。类型系统 + 构建期体检承担了测试的职责。

## 设计上的几个决定

**条形榜而不是环形图。** 条目是平铺的，有十几条。环形图的扇区上限在 6 个左右，十几个
扇区既画不开、也没有那么多色盲可分辨的颜色可用。横向条形对条目数量没有限制，而且长度
按同一基准并排，比角度好比较得多 —— 角度是出了名的难比较。

**整榜是单色的。** 给每个条配不同颜色，属于把「长度」这个信息用颜色再编码一遍，
白白烧掉唯一的身份通道，什么也没多告诉读者。资产用绿、负债用红，是一对**极性**色
（净值的一正一负两侧），不是身份色。

**配色是算出来的，不是挑的。** 绿红正是红绿色盲最经典的混淆对，所以这四个色值是
一条条搜出来的，不是挑的 —— 在明度带、色度下限、对比度、色盲可分辨性四项约束下
逐组合试到全部通过：

| 模式 | 资产      | 负债      | 色盲模拟 ΔE | 正常视觉 ΔE |
| ---- | --------- | --------- | ----------- | ----------- |
| 浅色 | `#078a07` | `#e34948` | 8.5         | 32.9        |
| 暗色 | `#0d940d` | `#e06a6a` | 9.6         | 32.3        |

换色前先跑 `dataviz` skill 里的 `scripts/validate_palette.js`，不要凭眼睛判断。
这一对能成立还有个前提：绿条和红条分处两个面板、各有标题和合计，
读者从不需要靠颜色分辨哪个是资产。如果以后改版把两者放进同一个图里比较，
就得换成色相离得更远的一对。

**负债率用仪表 + 文字档位。** 旁边永远有「稳健 / 适中 / 偏高 / 高」几个字。颜色从不
单独表意 —— 浅色模式下其中两档的对比度刻意低于 3:1，补偿通道就是那个文字标签。

**页面默认不被搜索引擎收录。** `app/robots.ts` 和 `<meta name="robots">` 两道闸都上了。
想公开被搜到的话，两处都要改。

## 部署

标准的 Next.js 静态站点，Vercel 直接导入即可。产物也能导出成纯静态文件（`out/`）丢到
任何静态托管，但因为目前没有用到任何服务端能力，两种方式行为完全一致。

**注意：`config/assets.yaml` 不在 git 里，所以从仓库部署时构建机会找不到它而失败。**
按仓库公开程度选一种：

| 情况                 | 做法                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 仓库私有，只有自己看 | `git add -f config/assets.yaml` 强制加进去（`-f` 是因为它被 gitignore 了）                                                                                                       |
| 仓库公开             | 别提交。改用构建前的环境变量或部署平台的「构建命令」把内容写进去，例如把 YAML 存成环境变量 `ASSETS_YAML`，构建命令设为 `printenv ASSETS_YAML > config/assets.yaml && pnpm build` |

无论哪种，**配置是构建期读的，不是运行期读的** —— 全站静态生成，配置在构建时
就烤进 HTML 了，改了必须重新构建才生效。

本地预览时注意：`pnpm start` 用的是启动那一刻加载的构建产物，
所以改完配置要 **`pnpm build` 重新构建 + 重启 `pnpm start`** 两步都做，
只重建不重启看不到变化。

（`pnpm dev` 不是这个规则 —— 它会按文件修改时间重新读配置，
改完刷新页面即可，见上面「改成你自己的数据」。）

## 已知限制

- **没有历史趋势。** 每次改配置都是覆盖当前快照。想做走势图的话，配置结构得改成多期。
- **只支持人民币。** 没有汇率换算，展示的每个数字都是配置里写的那个数字。
- **金额是手填的，不会自动更新。** 房产估值、基金市值都需要你自己定期改配置。
